# Трансляция заявок #KhromushkinTeam

GitHub Actions собирает и проверяет образ для `linux/amd64`, затем публикует его в GHCR. Для QNAP TS-462 подготовлен [запуск через Portainer](PORTAINER.md).

```text
ghcr.io/raidzer/moneyrun-relay:latest
```

Сборки запускаются при изменениях в `main` и вручную из вкладки Actions. В pull request выполняются сборка и тесты без публикации. У каждого опубликованного образа есть дополнительный тег `sha-<полный SHA коммита>` для выбора конкретной версии и отката. Публикация использует встроенный `GITHUB_TOKEN`; Telegram-токены для неё не нужны. [GitHub: публикация образов](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images).

Локальная программа читает выбранную группу через Telegram-аккаунт участника и отправляет новые тексты клуба через отдельного бота в группу «Заботы». Бот добавляется только в группу-получатель. Для чтения используется Telethon, для отправки — Telegram Bot API.

Источник может быть группой-форумом, в которой заявки публикует другой бот. Для чтения нужен пользовательский аккаунт с доступом к источнику. Интеграция напрямую с приложением Moneyrun не реализована. ID групп, токены и сохранённый вход задаются локально и не входят в репозиторий или образ.

## Отбор сообщений

Пример поддерживаемого формата, с вымышленными данными:

```text
#KhromushkinTeam

Пользователь Тестовый Атлет написал в тикет #123456

Хорошо, если ещё возникнут вопросы, мы всегда на связи!

Хороших тренировок 🙂
```

Отбирается сообщение, у которого первая непустая строка целиком совпадает с `#KhromushkinTeam`, без учёта регистра. Telegram хранит жирное/курсивное оформление отдельно от текста; вручную добавлять `**` в настройку не нужно. Упоминание клуба в середине чужого обращения и хэштег `#KhromushkinTeam2` не подходят.

Одинаково обрабатываются новые заявки и новые сообщения по существующим заявкам, **если они имеют такой заголовок**. Номер тикета не влияет на отбор: сообщения одного тикета не подавляют друг друга. Если новая заявка имеет другой формат или обновление приходит без хэштега, нужен ещё один пример для настройки отбора. Связь по ответам Telegram или номеру тикета в этой версии не восстанавливается.

Текст и подписи к вложениям передаются целиком, без жирного/курсивного оформления. Сами файлы не копируются. Для супергрупп добавляется кнопка открытия исходного сообщения; доступ по ней зависит от членства в источнике. Защищённое от пересылки содержимое не копируется.

## Подготовка

Нужен Python 3.12. Команды ниже выполняются в PowerShell из папки клонированного репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath 'config.json')) {
    Copy-Item -LiteralPath 'config.example.json' -Destination 'config.json'
}
```

Копирование нужно только один раз, пока `config.json` ещё не существует.

1. Открыть [my.telegram.org](https://my.telegram.org), войти и выбрать **API development tools**. Создать приложение и записать его `api_id` и `api_hash` в локальный `config.json`. `api_id` — число, `api_hash` — строка в кавычках.
2. Создать бота через [@BotFather](https://t.me/BotFather), командой `/newbot`. Добавить его в группу «Заботы» клуба с правом отправлять сообщения. Токен можно вписать в `bot_token` в локальном файле либо оставить поле пустым и ввести скрыто при запуске.
3. Аккаунт для чтения должен уже состоять в группе-источнике. Получить ID групп:

```powershell
.\.venv\Scripts\python.exe relay.py chats
```

При первом запуске Telegram запросит телефон, код входа и, если включена двухэтапная аутентификация, пароль. Ввести их непосредственно в своём терминале. `chats` выводит только названия и ID групп, без текстов сообщений. Группа-получатель также будет в списке, если аккаунт в ней состоит.

Вписать выбранные числовые ID в `source_chat_id` и `destination_chat_id`. В этой версии источник и получатель должны быть разными группами.

`source_topic_id` и `destination_topic_id` оставить `null`, если нужен весь источник и обычная группа-получатель. Для определённого топика указать его числовой ID. Его можно определить по ссылке на топик; если формат ссылки непонятен, достаточно передать помощнику эту ссылку без токенов. Для общего топика форума используется `1`.

API hash, токен, коды входа, пароль и файлы `.local/*.session` не нужно присылать в переписку. `.local/reader.session` сохраняет вход в Telegram; настройки, `.local/`, `Local/` и файлы сессий исключены из Git. `.dockerignore` допускает в контекст сборки только Dockerfile, сам `.dockerignore`, исходник и зависимости. Исключение из Git само по себе не шифрует файлы.

## Проверка и запуск

Показать подходящие тексты среди последних 50 сообщений выбранной группы:

```powershell
.\.venv\Scripts\python.exe relay.py preview
```

Предварительный просмотр ничего не отправляет и не меняет позицию рабочей пересылки. Если совпадений нет, подходящих сообщений может не быть в последних 50; также стоит проверить источник, топик и формат заголовка.

Запустить реальную отправку новых сообщений:

```powershell
.\.venv\Scripts\python.exe relay.py run
```

При **первом** запуске `run` программа сохраняет текущую позицию и ждёт новые сообщения. Старую историю она не пересылает. При последующих запусках обрабатывает доступные сообщения после сохранённой позиции, в том числе появившиеся во время остановки. Исходные сообщения не отмечаются прочитанными; ответы в Moneyrun не отправляются, статусы тикетов не меняются.

Проверка источника выполняется каждые 15 секунд; отправка ограничена одним сообщением примерно в 3,2 секунды. Остановка — `Ctrl+C`. Компьютер должен оставаться включённым, без сна, с доступом к Telegram. Запускается одна копия программы на эту папку.

Состояние хранится в `.local/state.json`. Перед отправкой сохраняется отметка `pending_id`, после подтверждения Telegram — новая позиция. Обычный перезапуск не повторяет обработанные сообщения. Если отправка осталась без подтверждения, программа останавливается и блокирует автоматическую повторную попытку. Нужно проверить группу-получатель и сохранить результат командой `resolve`; порядок действий описан в [инструкции Portainer](PORTAINER.md#если-доставка-осталась-без-подтверждения). Строго однократная доставка при любых сбоях диска или восстановлении старой копии не гарантируется.

Локальный вариант команды после проверки, при остановленной программе: `.\.venv\Scripts\python.exe relay.py resolve --message-id 123456 --result sent`. Вместо `123456` указать номер из ошибки. `sent` означает, что сообщение уже доставлено; `retry` разрешает повторную попытку при следующем запуске.

После смены маршрута программа не использует старое состояние автоматически. Для нового запуска нужно при остановленной программе переименовать `.local/state.json`, сохранив его копию; новый маршрут начнёт с текущих сообщений.

Редактирование и удаление старых сообщений не синхронизируются. Удалённые из источника во время простоя сообщения восстановить нельзя. Если бот удалён из получателя или потерял право писать, отправка остановится с ошибкой. После устранения причины нужно разрешить ожидающую отправку через `resolve`, если программа сообщает о ней, и запустить снова.

## Локальные проверки

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_relay.py
```

Проверяются фильтр клуба, ограничение по группе/топику, сохранность текста, ошибки записи и отправки, восстановление после перезапуска, остановка во время отправки и запуск без интерактивного входа. Используются искусственные сообщения; подключения к Telegram и отправки нет.

Для другого компьютера или сервера нужен Python 3.10+; окружение создаётся заново, а не переносится вместе с Windows `.venv`:

```text
python -m venv .venv
python -m pip --python .venv install -r requirements.txt
```

На Linux использовать `.venv/bin/python` вместо `.venv\Scripts\python.exe`. Для круглосуточного запуска подготовлен [вариант Docker/Portainer](PORTAINER.md).
