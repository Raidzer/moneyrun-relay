# Трансляция новых заявок и контроль первого ответа

GitHub Actions собирает и проверяет образ для `linux/amd64`, затем публикует его в GHCR. Для QNAP TS-462 подготовлен [запуск через Portainer](PORTAINER.md).

```text
ghcr.io/raidzer/moneyrun-relay:latest
```

Сборки запускаются при изменениях в `main` и вручную из вкладки Actions. В pull request выполняются сборка и тесты без публикации. У каждого опубликованного образа есть дополнительный тег `sha-<полный SHA коммита>` для выбора конкретной версии и отката. Публикация использует встроенный `GITHUB_TOKEN`; Telegram-токены для неё не нужны. [GitHub: публикация образов](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images).

Локальная программа читает выбранную группу через Telegram-аккаунт участника, отправляет новые тикеты клуба через отдельного бота в группу «Заботы» и напоминает об ожидающих первого ответа. Бот добавляется только в группу-получатель и должен быть её администратором. Для чтения используется Telethon, для отправки и административных команд — Telegram Bot API.

Источник может быть группой-форумом, в которой заявки публикует другой бот. Для чтения нужен пользовательский аккаунт с доступом к источнику. Интеграция напрямую с приложением Moneyrun не реализована. ID групп, токены и сохранённый вход задаются локально и не входят в репозиторий или образ.

## Отбор сообщений

Пример поддерживаемого формата, с вымышленными данными:

```text
#KhromushkinTeam

Пользователь Тестовый Атлет создал новый тикет #123456 - Вопрос

Не получается изменить настройку профиля.
```

Отбирается сообщение, у которого первая непустая строка целиком совпадает с `#KhromushkinTeam`, без учёта регистра. Telegram хранит жирное/курсивное оформление отдельно от текста; вручную добавлять `**` в настройку не нужно. Упоминание клуба в середине чужого обращения и хэштег `#KhromushkinTeam2` не подходят.

Сразу пересылаются только уведомления `Пользователь <имя> создал новый тикет #<номер> - <тема>`. Сообщения с заголовком `Пользователь <имя> написал в тикет #<номер>` используются для учёта ответа по этому номеру и не пересылаются. Сообщение автора обращения оставляет тикет ожидающим; первое сообщение другого человека исключает его из напоминаний навсегда. Это не закрывает тикет в самом Moneyrun.

Авторы сравниваются по именам в служебных заголовках с нормализацией регистра и пробелов. Смена имени или одинаковые имена разных людей могут повлиять на результат. Тело обращения не используется для распознавания событий. Нераспознанный заголовок отмечается в логе без вывода содержимого и не создаёт карточку.

Текст и подписи к вложениям передаются целиком, без жирного/курсивного оформления. Встроенные URL-ссылки сохраняются на исходных словах: имя пользователя и номер тикета остаются кликабельными с теми же адресами, что в источнике. Адреса не строятся по имени или номеру. Добавление анекдота не сдвигает ссылки; разовая отправка `test` также их сохраняет. Сами файлы не копируются. Для супергрупп добавляется кнопка открытия исходного сообщения; доступ по ней зависит от членства в источнике. Защищённое от пересылки содержимое не копируется.

## Подготовка

Нужен Python 3.12. Команды ниже выполняются в PowerShell из папки клонированного репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath 'config.json')) {
    Copy-Item -LiteralPath 'config.example.json' -Destination 'config.json'
}
```

Копирование нужно только один раз, пока `config.json` ещё не существует.

1. Открыть [my.telegram.org](https://my.telegram.org), войти и выбрать **API development tools**. Создать приложение и записать его `api_id` и `api_hash` в локальный `config.json`. `api_id` — число, `api_hash` — строка в кавычках.
2. Создать бота через [@BotFather](https://t.me/BotFather), командой `/newbot`. Добавить его администратором в группу «Заботы» клуба с правом отправлять сообщения: статус администратора необходим для проверки прав отправителей команд. Токен можно вписать в `bot_token` в локальном файле либо оставить поле пустым и ввести скрыто при запуске. У этого бота не должно быть другого обработчика `getUpdates` или webhook.
3. Аккаунт для чтения должен уже состоять в группе-источнике. Получить ID групп:

```powershell
.\.venv\Scripts\python.exe relay.py chats
```

При первом запуске Telegram запросит телефон, код входа и, если включена двухэтапная аутентификация, пароль. Ввести их непосредственно в своём терминале. `chats` выводит только названия и ID групп, без текстов сообщений. Группа-получатель также будет в списке, если аккаунт в ней состоит.

Вписать выбранные числовые ID в `source_chat_id` и `destination_chat_id`. В этой версии источник и получатель должны быть разными группами.

`source_topic_id` и `destination_topic_id` оставить `null`, если нужен весь источник и обычная группа-получатель. Для определённого топика указать его числовой ID. Его можно определить по ссылке на топик; если формат ссылки непонятен, достаточно передать помощнику эту ссылку без токенов. Для общего топика форума используется `1`.

API hash, токен, коды входа, пароль и файлы `.local/*.session` не нужно присылать в переписку. `.local/reader.session` сохраняет вход в Telegram; настройки, `.local/`, `Local/` и файлы сессий исключены из Git. `.dockerignore` допускает в контекст сборки только Dockerfile, сам `.dockerignore`, исходник и зависимости. Исключение из Git само по себе не шифрует файлы.

## Проверка и запуск

Показать подходящие тексты среди последних 50 сообщений выбранной группы:

```powershell
.\.venv\Scripts\python.exe relay.py preview
```

Предварительный просмотр ничего не отправляет и не меняет позицию рабочей пересылки. Если совпадений нет, подходящих сообщений может не быть в последних 50; также стоит проверить источник, топик и формат заголовка.

Для разового теста последних трёх сообщений клуба сначала остановить работающую пересылку, затем выполнить `python relay.py test --count 3 --send`. Без `--send` команда только показывает найденные сообщения. Поиск ограничен последними 1000 сообщениями источника и учитывает настроенный топик. Рабочая позиция не меняется; повторный запуск теста намеренно повторит сообщения. Порядок запуска в Docker описан в [инструкции Portainer](PORTAINER.md#разовая-отправка-последних-трёх-сообщений-клуба).

Запустить реальную отправку новых сообщений:

```powershell
.\.venv\Scripts\python.exe relay.py run
```

При **первом включении учёта тикетов**, включая переход со старой версии, программа создаёт пустую базу с текущей позицией источника. Старую историю не перечитывает и не пересылает. Если прежний `state.json` содержит неподтверждённую отправку, сначала нужна проверка и `resolve`. При последующих запусках обрабатываются доступные сообщения после сохранённой позиции, в том числе ответы за время остановки. Исходные сообщения не отмечаются прочитанными; ответы в Moneyrun не отправляются, статусы тикетов не меняются.

По умолчанию пауза ожидания новых сообщений — 15 секунд. Она задаётся переменной окружения `POLL_INTERVAL_SECONDS`: целое число секунд не меньше 1. Например, для 20 секунд в PowerShell:

```powershell
$env:POLL_INTERVAL_SECONDS = '20'
.\.venv\Scripts\python.exe relay.py run
```

В Portainer переменная задаётся в настройках Stack; см. [инструкцию](PORTAINER.md#интервал-опроса). Значение считывается при запуске и показывается в логе. Оно также задаёт паузу перед повторным чтением после ошибки связи. Паузы, которые требует Telegram через `FloodWait` или `retry_after`, соблюдаются отдельно. Изменение интервала не сбрасывает позицию пересылки.

Источник читается порциями по 100 сообщений до отбора по клубу. После полной порции следующая читается сразу, без паузы `POLL_INTERVAL_SECONDS`: так обрабатывается очередь за время простоя. После неполной или пустой порции бот ждёт настроенный интервал. Отправка по-прежнему ограничена одним сообщением примерно в 3,2 секунды; требуемые Telegram паузы также сохраняются, поэтому большое число заявок клуба всё равно требует времени на доставку. Остановка — `Ctrl+C`. Компьютер должен оставаться включённым, без сна, с доступом к Telegram. Запускается одна копия программы на эту папку.

Рабочее состояние хранится в `.local/tickets.sqlite3`; отдельный сервер БД и новые Python-зависимости не требуются. Карточка нового тикета и отметка `pending_id` сохраняются одной транзакцией до отправки, после подтверждения Telegram — новая позиция. Если отправка осталась без подтверждения, программа останавливается до проверки и `resolve`; карточка не теряется. Порядок действий описан в [инструкции Portainer](PORTAINER.md#если-доставка-осталась-без-подтверждения). Строго однократная доставка при любых сбоях диска или восстановлении старой копии не гарантируется.

Файл `.local/tracking.initialized` защищает от незаметного сброса при исчезновении БД. После перехода прежний `state.json` больше не отражает рабочую позицию. Не удалять БД или маркер для исправления ошибок. Резервную копию всей `.local` делать после остановки программы.

Локальный вариант команды после проверки, при остановленной программе: `.\.venv\Scripts\python.exe relay.py resolve --message-id 123456 --result sent`. Вместо `123456` указать номер из ошибки. `sent` означает, что сообщение уже доставлено; `retry` разрешает повторную попытку при следующем запуске.

После смены маршрута программа не использует прежнюю БД автоматически и не сбрасывает её. Потребуется явный перенос состояния либо отдельная папка данных для нового маршрута; сначала сохранить остановленную `.local` целиком.

## Анекдот в новой заявке

По умолчанию анекдоты **выключены** (`JOKES_ENABLED=false`), запросов к RSS нет. Для включения задать `JOKES_ENABLED=true` и перезапустить программу. Допустимы только `true`/`false` без учёта регистра и краевых пробелов; некорректное значение останавливает запуск до подключения к Telegram. В Logs выводится `Анекдоты: включены.` или `Анекдоты: выключены.`.

При включении к карточке создания нового тикета добавляется случайный русский анекдот из [RSS Анекдот.ру](https://www.anekdot.ru/static/rss.html): после разделителя `────────────`, с заголовком `😄 Анекдот` и ссылкой на источник. Тематических фильтров нет, возможны мат и содержание 18+. Анекдот — дополнение бота, он не входит в текст обращения в Moneyrun.

Подборка хранится в памяти и обновляется по мере прихода заявок не чаще раза в час. Выбор случайный из текущей ленты, поэтому повторы возможны. При ошибке загрузки бот ждёт не больше трёх секунд, затем использует прежнюю подборку или отправляет заявку без анекдота; следующий запрос к сайту — не раньше чем через пять минут. Данные тикета сервису не передаются.

Если карточка с анекдотом превысит лимит Telegram, бот отправляет полный исходный текст без дополнения. Обычные и срочные напоминания, ответы, команды, `preview` и разовая отправка `test` анекдоты не получают. Старые карточки не редактируются. Новых зависимостей и изменений БД нет. Для Portainer нужен актуальный [Compose и передача переменной](PORTAINER.md#анекдот-в-новой-заявке).

## Напоминания и команды

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `REMINDER_INTERVAL_HOURS` | `4` | Интервал обычной сводки, положительное целое число часов |
| `QUIET_HOURS_START` | `23:00` | Начало тихих часов по Москве (UTC+03:00) |
| `QUIET_HOURS_END` | `09:00` | Конец тихих часов, не включительно |

Начало и конец должны различаться; поддерживается переход через полночь. Первый интервал сводки отсчитывается от создания пустой базы. Если ожидающих нет, сообщения нет. В сводке — номера, авторы, темы, длительность ожидания и ссылки на создание. Большие списки делятся на несколько сообщений.

После **20 часов** от публикации уведомления о создании в Telegram тикет становится срочным. В заголовке срочного списка и отметке каждого срочного тикета после слова «Срочно» добавляются `❗❗❗`. Срочные списки повторяются каждые **30 минут**, включая ночь; обычная сводка также включает срочные тикеты. С 23:00 до 09:00 запрещены только обычные сводки. Сроки сохраняются после перезапуска; пропущенные рассылки не воспроизводятся по одной.

В группе-получателе администратор может отправить `/pause` — приостановить **все** напоминания, или `/resume` — возобновить их с учётом тихих часов. Новые тикеты, учёт ответов и реакции 👀 продолжают работать. Пауза сохраняется при перезапуске. Допускается `/pause@имя_бота`; команды от анонимного имени группы не исполняются. Подтверждение приходит в тему команды; при сбое отправки состояние уже сохранено.

При первом ответе другого человека в тикете Moneyrun бот ставит **👀 на свою карточку создания заявки** в группе клуба. Отдельное сообщение о взятии в работу не отправляется. Собственные продолжения автора не вызывают реакцию; последующие ответы не ставят её повторно. Реакция принадлежит боту и не показывает имя ответившего. В группе должна быть разрешена стандартная реакция 👀. [Telegram: реакции ботов](https://core.telegram.org/bots/api#setmessagereaction).

Реакции относятся только к карточкам, доставленным рабочим ботом после этого обновления: сохраняется ID целевого сообщения, старые сообщения не ищутся. Существующая SQLite-база обновляется автоматически без сброса тикетов, позиции, паузы и расписания. Старые тикеты по-прежнему снимаются с напоминаний после чужого ответа, но реакции на их карточки не добавляются. Разовая команда `test` не создаёт рабочие карточки для реакций.

Задание на реакцию сохраняется вместе с обработкой ответа и переживает перезапуск. Ночь и `/pause` его не откладывают. При ошибке реакции повтор происходит через 5 минут; при ограничении Telegram — не раньше указанного `retry_after`. Тикет остаётся обработанным, фоновый повтор не завершает рабочий процесс. Общий лимит Telegram может задержать доставку новой карточки и разбор следующих за ней событий. Повторная установка той же реакции безопасна. Если карточка удалена или 👀 запрещена, в журнале останется предупреждение и попытки будут повторяться.

Перед напоминанием бот успешно разбирает очередь источника; при отсутствии связи рассылка откладывается. Ошибка сводки не превращается в неподтверждённую отправку тикета. При `retry_after` срок паузы сохраняется, чтение продолжается, затем список строится заново. Неопределённый результат сводки не повторяется немедленно — следующая попытка по расписанию.

Если длинная сводка успела отправиться частично, оставшиеся части после ошибки попадут в следующую плановую рассылку. Таймеры уже отправленных частей не откатываются для немедленного повтора.

Редактирование и удаление старых сообщений не синхронизируются. Удалённые из источника во время простоя сообщения восстановить нельзя. Если бот удалён из получателя или потерял право писать, отправка остановится с ошибкой. После устранения причины нужно разрешить ожидающую отправку через `resolve`, если программа сообщает о ней, и запустить снова.

## Локальные проверки

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Проверяются фильтр клуба, создание и первый ответ, SQLite-транзакции и миграция, реакции и их восстановление, расписание/пауза/тихие часы, административные команды, ошибки отправки, анекдоты/кеш/отказ источника и первый запуск без истории. Используются искусственные сообщения и RSS; подключения к Telegram и отправки нет.

Для другого компьютера или сервера использовать Python 3.12; окружение создаётся заново, а не переносится вместе с Windows `.venv`:

```text
python -m venv .venv
python -m pip --python .venv install -r requirements.txt
```

На Linux использовать `.venv/bin/python` вместо `.venv\Scripts\python.exe`. Для круглосуточного запуска подготовлен [вариант Docker/Portainer](PORTAINER.md).
