# ADR 0002: Best-effort ИИ-рекомендации в карточке тикета

## Статус

Принято 23.11.2026.

## Решение

Новые карточки с событиями создания получают внутреннюю ИИ-рекомендацию после исходного текста. Рекомендация формируется через OpenAI-совместимый API, адрес и ключ которого задаются оператором в Docker. В запрос передаются очищенные тема и описание обращения, а не имя, номер тикета, ссылки или контактные данные.

Таблица «MR Забота» и официальный гайд загружаются один раз в сутки в 03:00 по Москве. Последняя полная удачная копия хранится в `.local/ai-knowledge.json`. Ошибка загрузки или API не должна блокировать доставку исходной карточки.

## Причины

Подсказка должна быть видна рядом с заявкой и проверяться сотрудником до ответа Атлету. Ожидание успешного ответа ИИ не может заменять доставку тикета и существующую гарантию сохранения позиции. Очистка текста уменьшает передачу персональных данных, а маркировка предупреждает о необходимости сверки с базой знаний.

## Последствия

ИИ не вызывается для ответов, напоминаний, `preview` и `test`. При отсутствии кеша карточка отправляется без подсказки. При повторной ручной отправке через `resolve retry` рекомендация может быть сформирована заново.
