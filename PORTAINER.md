# Запуск на QNAP TS-462 через Portainer

Для бота выбрана отдельная папка `/share/Container/moneyrun-relay`, рядом с Home Assistant. TS-462 использует x86-64; в Compose указана платформа `linux/amd64`. [Характеристики QNAP](https://www.qnap.com/en/product/ts-462/specs/hardware).

Инструкция рассчитана на **Docker Standalone** в Portainer. Готовый образ собирается в [GitHub Actions](https://github.com/Raidzer/moneyrun-relay/actions), а QNAP скачивает его из GHCR.

## 1. Перенести настройки и вход в Telegram

Если пересылка работает на компьютере, остановить её через `Ctrl+C` и дождаться завершения. С одной Telegram-сессией должна работать только одна копия программы.

В File Station создать папку `Container/moneyrun-relay`. Скопировать из локальной папки программы:

| На компьютере | На QNAP |
|---|---|
| Содержимое папки `.local` | `/share/Container/moneyrun-relay/Local` |

На QNAP создать папку **`Local` с большой L**, без точки. Скопировать в неё содержимое локальной `.local`, чтобы файл находился непосредственно по пути `Local/reader.session`, без дополнительной вложенной `.local`. Внутри контейнера эта папка подключается как `/app/.local` — так настроен Compose.

В `Local` нужен `reader.session`. Для переноса уже работающего учёта тикетов копировать всю папку, включая `tickets.sqlite3` и `tracking.initialized`: они сохраняют тикеты, позицию чтения, ручную паузу и расписания. Прежний `state.json` нужен только для проверки неподтверждённой отправки при первом переходе. Копировать после остановки программы, когда SQLite-сессия и база закрыты. Сессия позволяет войти без повторного кода, поэтому хранить эти файлы в папке с ограниченным доступом. [Telethon: сессии](https://docs.telethon.dev/en/stable/concepts/sessions.html).

Windows-папку `.venv` и файл `config.json` переносить не требуется. Значения прежнего JSON нужно внести в переменные Stack; таблица ниже. Для нового подключения сначала выполнить [локальную подготовку](README.md#подготовка).

## 2. Выбрать готовый образ

Используется образ:

```text
ghcr.io/raidzer/moneyrun-relay:latest
```

Он уже указан в Compose. При запуске Stack Portainer скачает его; вручную собирать образ и переносить исходники на NAS не требуется. Публичные образы GHCR доступны без авторизации. [GitHub Container registry](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry).

Если первая сборка ещё идёт, дождаться зелёного результата во вкладке Actions. У каждого образа есть точный тег `sha-<полный SHA коммита>`; его можно выбрать переменной Stack `RELAY_IMAGE` вместо `latest`.

Для владельца репозитория: после первой публикации GHCR создаёт пакет приватным даже у публичного репозитория. Один раз открыть пакет → **Package settings → Change visibility → Public**, подтвердить имя `moneyrun-relay`. Это необходимо для скачивания без токена. [GitHub: видимость пакетов](https://docs.github.com/en/packages/learn-github-packages/configuring-a-packages-access-control-and-visibility#configuring-visibility-of-packages-for-your-personal-account).

## 3. Создать Stack и запустить

Открыть **Stacks → Add stack**, имя `moneyrun-relay`, способ **Web editor**. Вставить целиком [compose.yaml](compose.yaml) и заполнить переменные ниже перед запуском. [Portainer: создание Stack](https://docs.portainer.io/sts/user/docker/stacks/add).

В **Environment variables** Stack внести настройки из прежнего `config.json`:

| Name | Взять из JSON |
|---|---|
| `API_ID` | `api_id` |
| `API_HASH` | `api_hash` |
| `BOT_TOKEN` | `bot_token` |
| `SOURCE_CHAT_ID` | `source_chat_id` |
| `SOURCE_TOPIC_ID` | `source_topic_id` |
| `DESTINATION_CHAT_ID` | `destination_chat_id` |
| `DESTINATION_TOPIC_ID` | `destination_topic_id` |
| `CLUB_HASHTAG` | `club_hashtag` |

Для тем `null` оставить пустое значение; остальные поля обязательны для рабочего запуска. ID чатов сохранять отрицательными, ID тем — положительными. Хэштег перенести с тем же написанием и регистром, чтобы маршрут совпал с сохранённым в БД. Значения вводятся без JSON-кавычек. Они подставляются в `${…}` из Compose; реальные ключи не вставлять в публичный YAML. [Portainer: переменные Stack](https://docs.portainer.io/user/docker/stacks/add).

Для другого пути данных задать `RELAY_DIR` с абсолютным путём **на QNAP**. Папка `Local` должна существовать до запуска; при обновлении сохранить её прежний путь и содержимое. Отдельный `config.json` контейнеру не нужен. Переменные доступны администраторам Portainer/Docker; они не заменяют разграничение доступа к серверу.

После заполнения настроек нажать **Deploy the stack**.

**Deploy запускает реальную пересылку новых тикетов клуба и напоминания.** Если `tickets.sqlite3` ещё нет, первый запуск начинает учёт с текущего момента с пустой базой. Если база перенесена, программа продолжает после сохранённого сообщения, включая доступные заявки и ответы за время остановки.

Контейнер использует скачанный образ, сохраняет данные в папке NAS и перезапускается после сбоя или перезагрузки NAS. Остановленный вручную контейнер остаётся остановленным. Порты открывать не требуется. Логи ограничены тремя файлами по 5 МБ. [Docker Compose: настройки сервиса](https://docs.docker.com/reference/compose-file/services/).

### Интервал опроса

В разделе **Environment variables** у Stack добавить:

| Name | Value |
|---|---|
| `POLL_INTERVAL_SECONDS` | `20` |

Это задаёт паузу 20 секунд при ожидании новых сообщений. Если переменная не задана, используется **15 секунд**. Допускается целое число не меньше 1. При ошибке значения программа завершится с понятным сообщением в Logs.

Накопившаяся очередь читается порциями по 100 сообщений до отбора по клубу: после полной порции следующая запрашивается сразу, после неполной или пустой — через заданный интервал. Между отправками остаётся пауза 3,2 секунды, а ограничения Telegram `FloodWait`/`retry_after` соблюдаются отдельно. При ошибке чтения перед повтором также выдерживается `POLL_INTERVAL_SECONDS`. Даже при значении 180 секунд успешное чтение полной очередной порции больше не вызывает трёхминутную паузу.

Для существующего Stack сначала вставить актуальный `compose.yaml`: в нём есть передача этой переменной в контейнер через `environment`. После изменения значения выполнить **Update the stack**. При первом переходе на эту версию также скачать новый образ. Последующие изменения интервала не требуют пересборки образа. Значение применяется при запуске контейнера; сохранённая позиция пересылки остаётся прежней.

### Напоминания и тихие часы

Актуальный `compose.yaml` также передаёт переменные:

| Name | Значение по умолчанию |
|---|---|
| `REMINDER_INTERVAL_HOURS` | `4` |
| `QUIET_HOURS_START` | `23:00` |
| `QUIET_HOURS_END` | `09:00` |

Первая переменная — интервал обычной сводки в часах, целое число не меньше 1. Время указывается строго `ЧЧ:ММ`, по Москве (UTC+03:00), начало и конец должны различаться. Для настройки добавить значения в переменные Stack и обновить контейнер. Если настройки подходят, дополнительные переменные задавать не нужно.

Сразу отправляются только **создания новых тикетов**. Ответ другого человека снимает обращение с напоминаний; сообщения открывшего не сбрасывают ожидание. Обычные сводки подавляются в тихие часы. После 20 часов ожидания срочные списки отправляются каждые 30 минут **даже ночью**.

Администратор группы может написать `/pause` или `/resume` в любой её теме; подтверждение придёт туда же. `/pause` отключает все напоминания, включая срочные, до `/resume`; новые тикеты, учёт ответов и реакции 👀 продолжаются. Пауза сохраняется при перезапуске. Анонимные команды от имени группы не исполняются; для адресации конкретному боту можно использовать `/pause@имя_бота`. Сам бот должен быть администратором. У него не должно быть webhook или другого работающего потребителя `getUpdates`.

### Реакция на взятую заявку

На карточках, которые рабочий бот прислал после обновления с этой функцией, первый ответ другого автора в самом тикете Moneyrun отмечается реакцией **👀 от бота**. Ответы создателя и последующие реплики реакции не вызывают. Отдельного сообщения о взятии в работу нет. Старые карточки не ищутся и не получают реакций; учёт первого ответа по ним продолжает работать.

В настройках группы-получателя разрешить 👀, если доступен только ограниченный набор реакций. Дополнительные переменные окружения и контейнер БД не нужны. Реакция работает ночью и при `/pause`; имя ответившего она не показывает. [Telegram: реакции ботов](https://core.telegram.org/bots/api#setmessagereaction).

Успех виден в Logs как `Поставлена реакция 👀 на тикет #…`. Если Telegram не подтвердил установку, задание сохраняется и повторяется через 5 минут (при `retry_after` — после указанной паузы), рабочий процесс не завершается. Карточка остаётся обработанной. Общий лимит Telegram может задержать отправку новой карточки и разбор событий за ней. При удалённой карточке или запрещённой реакции появится предупреждение; автоматический поиск замены сообщения не выполняется.

Перед обновлением остановить контейнер и сохранить копию всей `Local`. Существующая БД автоматически перейдёт с версии схемы 1 на 2 с сохранением тикетов, позиций, паузы и таймеров. При ошибке миграции базу не удалять. Откат к образу со схемой 1 требует и соответствующей резервной копии `Local`; старый образ не читает схему 2.

### Анекдот в новой заявке

Глобальная переменная **`JOKES_ENABLED`** включает анекдоты. По умолчанию `false` — анекдотов и запросов к сайту нет. Для включения вставить актуальный `compose.yaml` в редактор Stack и добавить в Environment variables `JOKES_ENABLED` со значением `true`, затем обновить Stack. Для отключения задать `false` и обновить Stack. Допустимы только `true` и `false`; одно добавление переменной в интерфейс Portainer без передачи через Compose не меняет окружение контейнера. При запуске Logs показывает `Анекдоты: включены.` или `Анекдоты: выключены.`.

При включении в новые карточки добавляется случайный анекдот на русском после разделителя, с указанием `Источник: https://www.anekdot.ru/`. Темы не фильтруются, возможны мат и содержание 18+. Бот читает общедоступную RSS-ленту сайта; ключи и регистрация не нужны. Подборка кешируется на час в памяти, повторы возможны. Напоминания, команды, ответы, тестовые отправки и старые карточки анекдотов не получают.

При обновлении сохранять прежние тома; схема БД не меняется. Если анекдоты включены, контейнеру нужен исходящий HTTPS-доступ к `www.anekdot.ru`; при недоступности загрузка ждёт не больше трёх секунд, затем используется прежняя подборка или заявка уходит без анекдота. После ошибки сайт опрашивается не чаще раза в пять минут. Длинный анекдот, который не помещается вместе с заявкой, пропускается; текст заявки не сокращается. Внешнему сайту данные обращений не передаются.

Встроенные URL-ссылки на имени пользователя и номере тикета сохраняются в новых карточках и разовой отправке `test`, независимо от `JOKES_ENABLED`. Старые карточки автоматически не редактируются; кнопка «Открыть в источнике» остаётся доступной.

### Первый переход с версии без учёта тикетов

Остановить основной контейнер и сохранить резервную копию всей `Local` и настроек Stack (либо прежнего `config.json`). Затем вставить актуальный Compose в редактор Stack, заполнить переменные и обновить со скачиванием `latest`, сохранив путь данных. Первый запуск создаст пустую `tickets.sqlite3` и `tracking.initialized` на текущей позиции источника, **без перечитывания старой истории**. Если была неподтверждённая отправка, сначала нужна проверка и `resolve`.

Последующие обновления сохраняют БД, паузу, таймеры и позицию. Не удалять БД/маркер, если программа сообщает об ошибке; исчезновение ранее созданной БД блокирует запуск с нуля. Резервную копию `Local` делать при остановленном контейнере. Сравнение авторов основано на отображаемых именах, поэтому одинаковые имена и смена имени могут влиять на снятие тикета с напоминаний.

## 4. Проверить работу

В **Containers** открыть контейнер этого Stack → **Logs**. При первом запуске ожидаются строки:

```text
Учёт тикетов начат с нуля. Старая история не читается и не пересылается.
Ожидание новых тикетов #KhromushkinTeam. Интервал опроса: 15 с. Остановка: Ctrl+C.
```

При переносе готовой базы первой строки не будет. Во второй строке показан фактический интервал из настроек. При новом тикете появится `Передано сообщение …`, а текст придёт в группу клуба. Ответы в существующие тикеты не пересылаются. Остановить контейнер можно кнопкой **Stop** в Portainer.

Если контейнер перезапускается, посмотреть ошибку в Logs. `Нет .local/reader.session` означает, что не перенесён файл или неверен путь. При недействительной сессии выполнить повторный вход на компьютере и перенести её после остановки. Контейнер не запрашивает телефон и код.

После каждой успешной проверки появляется строка с временем `Источник ответил: получено новых сообщений — N (до отбора по клубу).` Ноль означает, что Telegram ответил, но новых сообщений после сохранённой позиции нет. Это подтверждение чтения источника; доставку подтверждает отдельная строка `Передано сообщение …`.

`Server closed the connection: 0 bytes read on a total of 8 expected bytes` означает разрыв соединения чтения. Telethon автоматически пытается переподключиться. Если попытки исчерпаны, программа сообщает `Соединение с источником окончательно потеряно` и завершается с ошибкой, предварительно дождавшись начатой отправки карточки. Политика `restart: unless-stopped` запускает контейнер заново; при восстановлении сети чтение продолжается с сохранённой позиции. Неизвестный результат доставки по-прежнему блокирует работу до проверки и `resolve`. Если после ошибки снова появляется `Источник ответил`, чтение восстановлено. Если ошибок много, а успешных проверок нет, сохранить лог с временем за несколько интервалов опроса для диагностики сети и подключения. Не удалять сессию или базу: по одной этой строке причина разрыва неизвестна.

## Разовая отправка последних трёх сообщений клуба

Обновить основной Stack со скачиванием свежего образа, затем **остановить основной контейнер**. Тест использует ту же Telegram-сессию: одновременно запускать обе копии нельзя. Блокировка папки данных остановит вторую копию до подключения.

В Portainer открыть основной контейнер → **Duplicate/Edit**. Для копии задать имя `moneyrun-relay-test`, в **Command** указать:

```text
test --count 3 --send --non-interactive
```

**Entrypoint** сохранить `python relay.py`, переменные окружения и том `Local` оставить прежними. В **Restart policy** обязательно выбрать **Never**, чтобы тест не отправлялся по кругу. Создать копию через **Deploy the container**, открыть её **Logs**. Основной контейнер пока остаётся остановленным. [Portainer: копирование контейнера](https://docs.portainer.io/2.21/user/docker/containers/edit).

Команда ищет до трёх последних сообщений **от @FBR2BOT** (постоянный Telegram ID `265658465`) с хэштегом клуба в настроенном топике среди последних 1000 сообщений источника. Чужие пересланные копии не подходят. Отправляет найденные тексты в настроенную группу и тему, от старого к новому, с паузой 3,2 секунды. Если найдено меньше трёх, отправит столько, сколько нашла; количество видно в Logs. Для одного или двух сообщений поменять `--count`. Без `--send` будет только предварительный просмотр без отправки.

Тест **намеренно повторяет** выбранные сообщения, даже если бот уже передавал их раньше; он может выбрать и сообщения по существующим тикетам. Рабочие карточки, позиция, пауза и расписания в `Local/tickets.sqlite3` не меняются. Если тест захватил ещё не обработанное рабочим ботом создание тикета, основной процесс позже отправит его в обычном порядке.

Результат каждой попытки сохраняется отдельно в `Local/test-send-<идентификатор>.json`, имя выводится в Logs: `message_ids` — выбранные ID источника, `last_id` — последний подтверждённый ID, `pending_id` — отправка, результат которой ещё не подтверждён. При ошибке не перезапускать тест автоматически: сначала проверить тему назначения; сообщение могло дойти. Команда `resolve` относится только к рабочему состоянию, для тестового файла её применять не нужно.

После строки `Тест завершён: отправлено 3 сообщений.` проверить тексты в теме, удалить временный контейнер и запустить основной. Файлы `Local` не удалять. Тестовую команду не оставлять в основном Stack.

Для запуска из терминала при остановленном основном контейнере, наличии `compose.yaml` и заданных в терминале тех же переменных окружения (значения из интерфейса Portainer туда автоматически не передаются):

```sh
docker compose run --rm --no-deps relay test --count 3 --send --non-interactive
```

## Если доставка осталась без подтверждения

Перед отправкой программа записывает `pending_id`; после подтверждения Telegram сохраняет новую позицию и снимает отметку. Если процесс прерван между этими действиями, повторный запуск блокирует отправку и пишет номер исходного сообщения в Logs.

1. Остановить основной контейнер в Portainer.
2. Проверить в группе клуба, доставлен ли текст. Номер в ошибке относится к **источнику**; его можно сверить по кнопке «Открыть в источнике».
3. Сохранить результат командой `resolve`: `sent`, если сообщение уже есть; `retry`, если его нет и нужна повторная попытка. Не удалять `tickets.sqlite3`, `tracking.initialized` или прежний `state.json` для сброса ошибки.

В Portainer создать временный контейнер через **Containers → Add container**: имя `moneyrun-relay-resolve`, тот же образ, что у основного контейнера, принудительное скачивание отключено. В **Volumes** подключить прежнюю папку `Local` на QNAP → `/app/.local` (writable). В **Env** перенести пять переменных маршрута: `SOURCE_CHAT_ID`, `SOURCE_TOPIC_ID`, `DESTINATION_CHAT_ID`, `DESTINATION_TOPIC_ID`, `CLUB_HASHTAG`; API ID/hash и токен этому режиму не нужны. В **Command** задать `resolve --message-id 123456 --result sent`, заменив `123456` номером из ошибки; **Entrypoint** оставить исходным. Политика перезапуска — **Never**. Для повторной попытки заменить `sent` на `retry`. Прежний способ с read-only `config.json` тоже поддерживается.

Этот режим меняет только состояние на диске. После строки об успешном сохранении удалить временный контейнер и запустить основной. При выборе `retry` отправка произойдёт в основном контейнере. Это защита от автоматического повтора при неопределённом результате, а не гарантия строго однократной доставки при любых сбоях диска или восстановлении старых копий.

Установка 👀 использует отдельную очередь и не требует `resolve`: повтор одной и той же реакции не создаёт новое сообщение. Если доставку самой карточки пришлось подтвердить вручную через `resolve ... --result sent`, её целевой ID неизвестен — на этой карточке реакция недоступна, учёт ответов и напоминаний сохраняется.

## Обновление программы

При переходе с `config.json` на переменные сначала сохранить копию прежних настроек и остановленной `Local`. Заменить Compose на актуальный, внести восемь переменных из таблицы и обновить Stack со скачиванием образа. Новый Compose подключает только прежнюю `Local`; файл настроек больше не монтируется. База, сессия, пауза, расписание и позиция сохраняются, миграция схемы не требуется. Другую папку данных не выбирать: пустая существующая папка будет считаться первым запуском. Старый Compose с файлом продолжает работать при обновлении одного образа; переменные имеют приоритет над файлом. Резервную копию конфигурации хранить с ограниченным доступом.

Отправить изменения в `main` и дождаться успешной сборки в Actions. В Portainer открыть Stack → **Editor → Update the stack**, включив скачивание обновлённого образа, если интерфейс предлагает такую опцию. Сохранить прежние пути томов: так останутся Telegram-сессия и позиция пересылки. Публикация новой версии в GHCR сама по себе не обновляет уже работающий контейнер на NAS.

Для выбора точной версии задать `RELAY_IMAGE=ghcr.io/raidzer/moneyrun-relay:sha-<полный SHA коммита>` и обновить Stack. Адрес версии записывается в итогах каждой успешной сборки Actions. Откат с SQLite-учёта к старой версии без него требует резервной копии `Local` до перехода: прежний `state.json` больше не содержит актуальную позицию. Смена одного образа может повторно отправить старые сообщения.
