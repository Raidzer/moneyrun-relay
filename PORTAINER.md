# Запуск на QNAP TS-462 через Portainer

Для бота выбрана отдельная папка `/share/Container/moneyrun-relay`, рядом с Home Assistant. TS-462 использует x86-64; в Compose указана платформа `linux/amd64`. [Характеристики QNAP](https://www.qnap.com/en/product/ts-462/specs/hardware).

Инструкция рассчитана на **Docker Standalone** в Portainer. Готовый образ собирается в [GitHub Actions](https://github.com/Raidzer/moneyrun-relay/actions), а QNAP скачивает его из GHCR.

## 1. Перенести настройки и вход в Telegram

Если пересылка работает на компьютере, остановить её через `Ctrl+C` и дождаться завершения. С одной Telegram-сессией должна работать только одна копия программы.

В File Station создать папку `Container/moneyrun-relay`. Скопировать из локальной папки программы:

| На компьютере | На QNAP |
|---|---|
| `config.json` | `/share/Container/moneyrun-relay/config.json` |
| Содержимое папки `.local` | `/share/Container/moneyrun-relay/Local` |

На QNAP создать папку **`Local` с большой L**, без точки. Скопировать в неё содержимое локальной `.local`, чтобы файл находился непосредственно по пути `Local/reader.session`, без дополнительной вложенной `.local`. Внутри контейнера эта папка подключается как `/app/.local` — так настроен Compose.

В `Local` нужен `reader.session`. Если есть `state.json`, перенести и его — он сохраняет позицию пересылки. Копировать после остановки программы, когда SQLite-сессия закрыта. Сессия позволяет войти без повторного кода, поэтому хранить эти файлы в папке с ограниченным доступом. [Telethon: сессии](https://docs.telethon.dev/en/stable/concepts/sessions.html).

Windows-папку `.venv` переносить не требуется. Если программа уже работает локально, использовать её заполненный `config.json`. Для нового подключения сначала выполнить [локальную подготовку](README.md#подготовка).

## 2. Выбрать готовый образ

Используется образ:

```text
ghcr.io/raidzer/moneyrun-relay:latest
```

Он уже указан в Compose. При запуске Stack Portainer скачает его; вручную собирать образ и переносить исходники на NAS не требуется. Публичные образы GHCR доступны без авторизации. [GitHub Container registry](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry).

Если первая сборка ещё идёт, дождаться зелёного результата во вкладке Actions. У каждого образа есть точный тег `sha-<полный SHA коммита>`; его можно выбрать переменной Stack `RELAY_IMAGE` вместо `latest`.

Для владельца репозитория: после первой публикации GHCR создаёт пакет приватным даже у публичного репозитория. Один раз открыть пакет → **Package settings → Change visibility → Public**, подтвердить имя `moneyrun-relay`. Это необходимо для скачивания без токена. [GitHub: видимость пакетов](https://docs.github.com/en/packages/learn-github-packages/configuring-a-packages-access-control-and-visibility#configuring-visibility-of-packages-for-your-personal-account).

## 3. Создать Stack и запустить

Открыть **Stacks → Add stack**, имя `moneyrun-relay`, способ **Web editor**. Вставить целиком [compose.yaml](compose.yaml) и нажать **Deploy the stack**. [Portainer: создание Stack](https://docs.portainer.io/sts/user/docker/stacks/add).

При выбранной папке дополнительные переменные не нужны. Для другого пути задать в Stack переменную `RELAY_DIR` с абсолютным путём **на QNAP**. Файл `config.json` и папка `Local` должны существовать до запуска.

**Deploy запускает реальную пересылку новых сообщений клуба.** Если `state.json` ещё нет, программа начинает с текущего момента. Если состояние перенесено, продолжает после сохранённого сообщения, включая доступные заявки за время остановки.

Контейнер использует скачанный образ, сохраняет данные в папке NAS и перезапускается после сбоя или перезагрузки NAS. Остановленный вручную контейнер остаётся остановленным. Порты открывать не требуется. Логи ограничены тремя файлами по 5 МБ. [Docker Compose: настройки сервиса](https://docs.docker.com/reference/compose-file/services/).

### Интервал опроса

В разделе **Environment variables** у Stack добавить:

| Name | Value |
|---|---|
| `POLL_INTERVAL_SECONDS` | `60` |

Это задаёт паузу 60 секунд между проверками. Если переменная не задана, используется **15 секунд**. Допускается целое число не меньше 1. При ошибке значения программа завершится с понятным сообщением в Logs.

Для существующего Stack сначала вставить актуальный `compose.yaml`: в нём есть передача этой переменной в контейнер через `environment`. После изменения значения выполнить **Update the stack**. При первом переходе на эту версию также скачать новый образ. Последующие изменения интервала не требуют пересборки образа. Значение применяется при запуске контейнера; сохранённая позиция пересылки остаётся прежней.

## 4. Проверить работу

В **Containers** открыть контейнер этого Stack → **Logs**. При первом запуске ожидаются строки:

```text
Начальная точка сохранена. История не пересылается.
Ожидание новых сообщений #KhromushkinTeam. Интервал опроса: 15 с. Остановка: Ctrl+C.
```

При переносе готового состояния первой строки не будет. Во второй строке показан фактический интервал из настроек. При новой подходящей заявке появится `Передано сообщение …`, а текст придёт в группу клуба. Остановить контейнер можно кнопкой **Stop** в Portainer.

Если контейнер перезапускается, посмотреть ошибку в Logs. `Нет .local/reader.session` означает, что не перенесён файл или неверен путь. При недействительной сессии выполнить повторный вход на компьютере и перенести её после остановки. Контейнер не запрашивает телефон и код.

После каждой успешной проверки появляется строка с временем `Источник ответил: получено новых сообщений — N (до отбора по клубу).` Ноль означает, что Telegram ответил, но новых сообщений после сохранённой позиции нет. Это подтверждение чтения источника; доставку подтверждает отдельная строка `Передано сообщение …`.

`Server closed the connection: 0 bytes read on a total of 8 expected bytes` означает разрыв соединения чтения. Telethon автоматически пытается переподключиться. Если после ошибки снова появляется `Источник ответил`, чтение восстановлено. Если ошибок много, а успешных проверок нет, сохранить лог с временем за несколько интервалов опроса для диагностики сети и подключения. Не удалять сессию или `state.json`: по одной этой строке причина разрыва неизвестна.

## Разовая отправка последних трёх сообщений клуба

Обновить основной Stack со скачиванием свежего образа, затем **остановить основной контейнер**. Тест использует ту же Telegram-сессию: одновременно запускать обе копии нельзя. Блокировка папки данных остановит вторую копию до подключения.

В Portainer открыть основной контейнер → **Duplicate/Edit**. Для копии задать имя `moneyrun-relay-test`, в **Command** указать:

```text
test --count 3 --send --non-interactive
```

**Entrypoint** сохранить `python relay.py`, пути обоих томов оставить прежними. В **Restart policy** обязательно выбрать **Never**, чтобы тест не отправлялся по кругу. Создать копию через **Deploy the container**, открыть её **Logs**. Основной контейнер пока остаётся остановленным. [Portainer: копирование контейнера](https://docs.portainer.io/2.21/user/docker/containers/edit).

Команда ищет до трёх последних сообщений с хэштегом клуба в настроенном топике среди последних 1000 сообщений источника. Отправляет найденные тексты в настроенную группу и тему, от старого к новому, с паузой 3,2 секунды. Если найдено меньше трёх, отправит столько, сколько нашла; количество видно в Logs. Для одного или двух сообщений поменять `--count`. Без `--send` будет только предварительный просмотр без отправки.

Тест **намеренно повторяет** выбранные сообщения, даже если бот уже передавал их раньше. Позиция обычной пересылки `Local/state.json` не меняется. Если тест захватил ещё не обработанное рабочим ботом сообщение, основной процесс позже отправит его в обычном порядке.

Результат каждой попытки сохраняется отдельно в `Local/test-send-<идентификатор>.json`, имя выводится в Logs: `message_ids` — выбранные ID источника, `last_id` — последний подтверждённый ID, `pending_id` — отправка, результат которой ещё не подтверждён. При ошибке не перезапускать тест автоматически: сначала проверить тему назначения; сообщение могло дойти. Команда `resolve` относится только к рабочему состоянию, для тестового файла её применять не нужно.

После строки `Тест завершён: отправлено 3 сообщений.` проверить тексты в теме, удалить временный контейнер и запустить основной. Файлы `Local` не удалять. Тестовую команду не оставлять в основном Stack.

Для запуска из терминала при остановленном основном контейнере и наличии `compose.yaml`:

```sh
docker compose run --rm --no-deps relay test --count 3 --send --non-interactive
```

## Если доставка осталась без подтверждения

Перед отправкой программа записывает `pending_id`; после подтверждения Telegram сохраняет новую позицию и снимает отметку. Если процесс прерван между этими действиями, повторный запуск блокирует отправку и пишет номер исходного сообщения в Logs.

1. Остановить основной контейнер в Portainer.
2. Проверить в группе клуба, доставлен ли текст. Номер в ошибке относится к **источнику**; его можно сверить по кнопке «Открыть в источнике».
3. Сохранить результат командой `resolve`: `sent`, если сообщение уже есть; `retry`, если его нет и нужна повторная попытка. Не удалять `state.json` — это потеряет позицию.

В Portainer создать временный контейнер через **Containers → Add container**: имя `moneyrun-relay-resolve`, тот же образ, что у основного контейнера, принудительное скачивание отключено. В **Volumes** добавить bind mounts: файл настроек → `/app/config.json` (read-only), папка `Local` на QNAP → `/app/.local` (writable). В **Command** задать `resolve --message-id 123456 --result sent`, заменив `123456` номером из ошибки; **Entrypoint** оставить исходным. Политика перезапуска — **Never**. Для повторной попытки заменить `sent` на `retry`.

Этот режим меняет только состояние на диске. После строки об успешном сохранении удалить временный контейнер и запустить основной. При выборе `retry` отправка произойдёт в основном контейнере. Это защита от автоматического повтора при неопределённом результате, а не гарантия строго однократной доставки при любых сбоях диска или восстановлении старых копий.

## Обновление программы

Отправить изменения в `main` и дождаться успешной сборки в Actions. В Portainer открыть Stack → **Editor → Update the stack**, включив скачивание обновлённого образа, если интерфейс предлагает такую опцию. Сохранить прежние пути томов: так останутся Telegram-сессия и позиция пересылки. Публикация новой версии в GHCR сама по себе не обновляет уже работающий контейнер на NAS.

Для отката задать `RELAY_IMAGE=ghcr.io/raidzer/moneyrun-relay:sha-<полный SHA предыдущего коммита>` и обновить Stack. Адрес точной версии записывается в итогах каждой успешной сборки Actions.
